# TAE Week 4 Capstone — Incident Command MCP Agent

Runnable Python package that delivers the Week 4 capstone: an MCP server
advertising three tools plus one resource surface, and an orchestrator that
cycles through **Observe → Plan → Act → Learn** with enforced budgets,
correlation IDs, structured logging, and replayable transcripts.

Mapping to the handout (MCP Agents — Systems Note & Capstone Guide):

## Layout

```
incident_agent/
  schemas.py        JSON schemas + minimal validator
  memory.py         MemoryStore + MemoryDelta + correlation-ID helpers
  server.py         MCP server: tool handlers, resource surface, dispatch
  orchestrator.py   Observe→Plan→Act→Learn loop, FSM planner, budgets, replay
  cli.py            argparse CLI: run-demo, replay, show-capabilities
tests/
  test_tools.py     Per-tool unit tests + JSON-RPC error paths
  test_loop.py      Integration test: full loop + replay determinism + budget abort
artifacts/
  sample_trace.jsonl   Generated by `run-demo`
  sample_summary.md    Human-readable handoff produced at loop end
config.yaml         Tool registry, budgets, planner FSM, telemetry paths
```

transcript (one JSON object per line). The `artifacts/sample_summary.md`
contains the human-readable handoff markdown that an on-call engineer would
receive.

## Replay a trace (no live tools)

```bash
python -m incident_agent.cli replay artifacts/sample_trace.jsonl
```

This runs the orchestrator against a stub transport that serves recorded
responses in order. Handout §5.6 item 3.

## Run tests

```bash
pip install pytest
pytest -q
```

Seven unit tests on tool handlers (schema validation, happy paths, JSON-RPC
error codes) + six integration tests covering:

- full OPAL loop produces a handoff
- loop invokes ≥1 retrieval and ≥1 diagnostic and a final summary
- handoff references evidence and recommendations
- correlation IDs are unique
- latency budget aborts the loop
- replay reproduces the handoff bit-for-bit

## Rubric coverage

- [x] **Correctness** — MCP initialize + resource exposure + tool invocation all work; a full OPAL loop completes and produces a handoff
- [x] **Engineering hygiene** — explicit `Budgets`, correlation IDs per loop, structured logging, replay trace + transcript, YAML config
- [x] **Reporting** — README, sample summary, run-record fields (`loops_run`, `tool_calls`, `total_latency_ms`, `terminated_reason`), human-readable handoff

## Optional Colab path (§7)

The package is importable; you can mirror the demo inside a Colab notebook:

```python
from incident_agent.server import IncidentMCPServer
from incident_agent.orchestrator import IncidentOrchestrator, Budgets
from incident_agent.memory import MemoryStore
memory = MemoryStore()
server = IncidentMCPServer(memory=memory)
orch = IncidentOrchestrator(rpc=server.handle, memory=memory,
                            budgets=Budgets(max_loops=4, max_latency_ms=2000,
                                            max_tool_calls=8, max_per_tool={}))
print(orch.run({"id": "ALRT-2025-07", "service": "staging-api",
                "symptom": "CPU spike", "severity": "high"}))
```

For a live WebSocket MCP server (as in handout §6), swap `server.handle` for a
thin WebSocket client wrapper; the orchestrator does not care about transport.
